# SnowGauge — project context for Claude

Low-cost, low-power snow depth logger (NIR laser ToF + XIAO nRF52840 Sense). Field trial starts 2026-12-31; student assembly session on 2026-09-17.

## Current state (2026-09-03, end of session)

**Hardware**
- PCB v1.2 ordered at JLCPCB (64×50mm, gerbers = `pcb/SnowGauge_v1.2_gerbers.zip`), ETA ~2026-09-10. Two independent design reviews passed. Known accepted margins: RX/Q2-pad clearances ~0.37mm; ADC reads Vbat/2 ≈3.5V max on fresh cells.
- **Breadboard is fully built and verified (STEP 1–5)**. Guide: `docs/breadboard_guide.html`, generated by `docs/gen_breadboard.py` (never hand-edit the HTML; edit `PARTS` and rerun). XIAO sits USB-left, which puts **top row (e20–e26) = 5V,GND,3V3,D10,D9,D8,D7 and bottom row (f20–f26) = D0/A0…D6** — the old guide had this swapped. Resistor substitutes on the board: R3=150Ω, R4=R5=10k, R1=R2=5k, R7=2.2k (note in guide §4). Bench PSU 6.0 V replaces the L91 pack; **picowatt** (user's INA228 tool, `~/NIES/picowatt`, port `/dev/cu.usbmodem214xx`) sits in the supply line.
- Bench rule: USB and battery/PSU may coexist only with jumper ⑩ (a10→a22, U1 3.3 V → XIAO 3V3) pulled. Flashing needs USB (⑩ out); sleep tests need USB out and ⑩ in. At session end the board was on PSU only with ⑩ in.

**Firmware (`firmware/`, NCS v3.4.0)** — steps 1–3 done and measured; next is **step 4 (BLE + record storage)**.
- Verified: rail switch, TFmini 100 Hz burst (median/variance/strength/temp, 0 checksum errors), battery ADC, IMU tilt (LSM6DS3TR-C, supply-gated), QSPI deep power-down, VBUS-gated USB, shell over USB CDC (`rail`, `tfmini`, `batt`, `tilt`, `measure`, `auto`, `dfu`, `device list`, `sensor`).
- **Measured on the breadboard** (`docs/measurements/2026-09-03_breadboard_current.md`): sleep **17 µA ±10** (whole system), measurement burst 1.58 s / 0.037 mAh, i.e. ≈21 µA average before BLE. The 1.89 mA trap: Zephyr's udc_nrf keeps HFXO+USBD on whenever the USB device is enabled, regardless of VBUS → `usb_pm.c` enables it only while VBUS is present (`CONFIG_CDC_ACM_SERIAL_ENABLE_AT_BOOT=n`).
- IMU gotcha: board regulator delay (3 ms) is too short → `zephyr,deferred-init` on the sensor node and `device_init()` after 30 ms in `tilt_init()`.
- The board currently runs the **auto-60 s test build** (`-DEXTRA_CONF_FILE=overlay-auto60.conf`, measures every 60 s, green LED pulse). Default build has auto period 0 (shell only). `CONFIG_SENSOR_SHELL`/`CONFIG_DEVICE_SHELL` are left on for debugging (~13 KB flash).
- TFmini "chip temp" (~50–75 °C) is the sensor's internal temperature; use the IMU temperature as the environment proxy.

**Step 4 plan (agreed)**: (a) record format (~40 B: time, dist median/var, strength, out-of-range count, tilt, temp, Vbat) + LittleFS on the QSPI (`p25q16h`, driver already on, keep DPD when idle) + internal-flash mirror + RTC/time-of-day source; (b) BLE advertising with Manufacturer Data (Vbat, record count, last distance, error flags), interval 1–2 s — measure the current increment with picowatt; (c) SMP/mcumgr fs + os (datetime) for nRF Connect Device Manager; (d) custom calibration GATT (live stream, ZERO, ERASE). Then step 5 (TSD20 driver variant).

**Tooling on this Mac**
- NCS v3.4.0 at `/opt/nordic/ncs/v3.4.0` (`~/.local/bin/nrfutil sdk-manager`). Build: `cd /opt/nordic/ncs/v3.4.0 && nrfutil sdk-manager toolchain launch --ncs-version v3.4.0 -- west build -d <repo>/firmware/build -b xiao_ble/nrf52840/sense <repo>/firmware [-- -DEXTRA_CONF_FILE=overlay-auto60.conf]`. Output `firmware/build/firmware/zephyr/zephyr.{hex,uf2}`.
- **Flashing**: macOS 26 cannot mount the XIAO's Adafruit-bootloader UF2 drive. Use serial DFU: `adafruit-nrfutil dfu genpkg --dev-type 0x0052 --sd-req 0xFFFE --application zephyr.hex pkg.zip`; put the board in the bootloader (shell `dfu`, or double-tap reset); `adafruit-nrfutil dfu serial --package pkg.zip -p /dev/cu.usbmodem21101 -b 115200 --singlebank`. `--sd-req 0x00` makes the bootloader reject and reset mid-transfer. adafruit-nrfutil + pyserial live in a scratch venv (`pip install adafruit-nrfutil pyserial`).
- Shell driving: a tiny pyserial script sending commands to `/dev/cu.usbmodem21101` at 115200 works; strip ANSI codes.
- picowatt capture: `cd ~/NIES/picowatt/app && uv run picowatt-cli --port /dev/cu.usbmodem214xx --mode single --adcrange 1 --preset very-quiet --seconds N --csv out.csv` (7.6 Sa/s, 2 µA LSB). µA-level absolute values need the difference method described in the measurements doc.
- MCUboot would overwrite the Adafruit bootloader → needs SWD; decided against for v1 (spec v0.11).

## Firmware decisions (spec §12, closed)

- **nRF Connect SDK (Zephyr)**, board `xiao_ble/nrf52840/sense`. **Flashing is USB/UF2 only (decided 2026-09-02, no SWD probe): keep the Adafruit bootloader, no MCUboot, BLE DFU deferred to a future revision.**
- BLE: SMP/mcumgr (LittleFS file download + datetime; img mgmt/DFU off) → works with nRF Connect Device Manager app (iOS/Android). Custom GATT only for calibration live-stream/ZERO/ERASE. Advertising carries battery/record-count/last-distance in Manufacturer Data.
- Records: LittleFS on 2MB QSPI (deep power-down when idle!), mirror to internal flash. IMU (LSM6DS3TR-C) behind a `TiltSensor` abstraction.
- Key GPIO (v1.2): **D10=SENSOR_EN** (high = sensor rail on), **A0=battery divider** (enable SENSOR_EN first, read ×2; node is 0V in sleep — D3/Q3 no longer exist), D6/D7=UART to TFmini (**set TX Hi-Z/low before cutting the rail** — ghost-powering), D4/D5 spare I2C.
- Power budget: sleep ≤90µA worst (target ~50µA); measure 8×/day, N samples → median+variance+quality flags (TFmini sentinel vs TSD20 sentinel 50000).
