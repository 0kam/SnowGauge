# SnowGauge — project context for Claude

Low-cost, low-power snow depth logger (NIR laser ToF + XIAO nRF52840 Sense). Field trial starts 2026-12-31; student assembly session on 2026-09-17.

## Single sources of truth

- Requirements/architecture: `SnowGauge_設計仕様書_v0.11.md` (Japanese; full-revision policy — bump the version on every change)
- **Pin map & electrical topology: `pcb/README.md`** (PCB v1.2). Anything else (older docs, §4 of the spec) is superseded where they disagree.
- PCB is generated by `pcb/generate_board.py` (KiCad 10 pcbnew script). Never hand-edit `SnowGauge.kicad_pcb`; edit the script, regenerate, run DRC via kicad-cli, re-export gerbers.

## Current state (2026-09-02)

- PCB v1.2 ordered at JLCPCB (64×50mm, gerbers = `pcb/SnowGauge_v1.2_gerbers.zip`), ETA ~2026-09-10.
- Development proceeds on a breadboard meanwhile: `docs/breadboard_guide.html` (same v1.2 topology — FW written against it runs unchanged on the PCB).
- Two independent design reviews passed (electrical netlist extraction + physical/fab). Known accepted margins: RX/Q2-pad clearances ~0.37mm; ADC reads Vbat/2 ≈3.5V max on fresh cells (within SAADC 3.6V FS).
- **Firmware step 1 done and verified on the breadboard (2026-09-03)**: sensor rail on/off, TFmini frames at 100 Hz with zero checksum errors (197 cm, strength ~6800), battery ADC (5.62 V under load from a 6 V bench supply). See `firmware/README.md` for build/flash/bench commands.
- **Flashing on this Mac**: the XIAO's stock Adafruit bootloader (0.6.x) exposes a UF2 drive that macOS 26 cannot read ("disk not readable"). Use serial DFU instead: `adafruit-nrfutil dfu genpkg --dev-type 0x0052 --sd-req 0xFFFE --application zephyr.hex pkg.zip` then `adafruit-nrfutil dfu serial --package pkg.zip -p /dev/cu.usbmodem* -b 115200 --singlebank` while the board is in the bootloader (double-tap reset, or the FW `dfu` shell command). `--sd-req 0x00` makes the bootloader reject and reset. adafruit-nrfutil lives in a scratch venv; `pip install adafruit-nrfutil` recreates it.
- Breadboard: `docs/gen_breadboard.py` generates `docs/breadboard_guide.html` (never hand-edit the HTML). Resistor substitutes used on the current breadboard: R3=150Ω, R4=R5=10k, R1=R2=5k, R7=2.2k.
- Toolchain: nRF Connect SDK **v3.4.0** at `/opt/nordic/ncs/v3.4.0`, installed via `~/.local/bin/nrfutil sdk-manager`. Build must run from the SDK workspace dir: `cd /opt/nordic/ncs/v3.4.0 && nrfutil sdk-manager toolchain launch --ncs-version v3.4.0 -- west build -d <repo>/firmware/build -b xiao_ble/nrf52840/sense <repo>/firmware`.
- Board note: the xiao_ble board already puts console/shell on USB CDC ACM (`board_cdc_acm_uart`, USB device_next stack); uart0 (D6/D7) is free for the TFmini. MCUboot would overwrite the Adafruit UF2 bootloader → needs an SWD probe; decided against for v1 (spec v0.11).

## Firmware decisions (spec §12, closed)

- **nRF Connect SDK (Zephyr)**, board `xiao_ble/nrf52840/sense`. **Flashing is USB/UF2 only (decided 2026-09-02, no SWD probe): keep the Adafruit bootloader, no MCUboot, BLE DFU deferred to a future revision.**
- BLE: SMP/mcumgr (LittleFS file download + datetime; img mgmt/DFU off) → works with nRF Connect Device Manager app (iOS/Android). Custom GATT only for calibration live-stream/ZERO/ERASE. Advertising carries battery/record-count/last-distance in Manufacturer Data.
- Records: LittleFS on 2MB QSPI (deep power-down when idle!), mirror to internal flash. IMU (LSM6DS3TR-C) behind a `TiltSensor` abstraction.
- Key GPIO (v1.2): **D10=SENSOR_EN** (high = sensor rail on), **A0=battery divider** (enable SENSOR_EN first, read ×2; node is 0V in sleep — D3/Q3 no longer exist), D6/D7=UART to TFmini (**set TX Hi-Z/low before cutting the rail** — ghost-powering), D4/D5 spare I2C.
- Power budget: sleep ≤90µA worst (target ~50µA); measure 8×/day, N samples → median+variance+quality flags (TFmini sentinel vs TSD20 sentinel 50000).

## FW development order (agreed with user)

1. Zephyr scaffold + TFmini UART test FW (breadboard STEP 5 check uses it)
2. Measurement sequence (rail switch, N-sample median/variance, IMU tilt, battery ADC)
3. Sleep-current tuning (QSPI power-down, IMU off, BLE adv 1–2s)
4. BLE (SMP + custom calibration service), record storage
5. TSD20 driver variant (frame format + sentinel differ; same board with U2=F33)
