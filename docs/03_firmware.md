# 03. ファームウェアの書き込み

SnowGauge 本体（XIAO nRF52840 Sense）に、公開済みのファームウェア（本体のプログラム）を書き込む手順です。
工学の知識は不要です。書いてあるとおりに進めてください。

- 本体を自分で組み立てた直後（初回の書き込み）
- 新しい版のファームウェアが出たとき（更新）

のどちらも、この手順で行います。書き込みは USB 経由で行い、**設定・記録データは消えません**（記録は QSPI フラッシュに、設定は別領域に入っています）。

---

## 1. 用意するもの

| もの | 備考 |
|---|---|
| USB-C ケーブル | **データ通信対応**のもの。充電専用ケーブルでは PC に認識されません |
| PC | Windows / macOS / Linux のいずれか。Chrome が入っていると後の確認（04 章）にも使えます |
| SnowGauge 本体 | XIAO が載った基板（または開発用ブレッドボード） |

### 安全上のきまり（必ず守る）

> **USB と電池（または安定化電源）を同時につながない。**
> - **基板（PCB）**: USB をつなぐ前に**電池を外す**。書き込みが終わって USB を抜いてから電池をつなぐ。
> - **ブレッドボード**: ジャンパ ⑩ を抜いてあるときだけ同時接続可（`docs/breadboard_guide.html` 参照）。抜いていなければ USB をつなぐ前に電源を外す。

---

## 2. ファームウェアをダウンロードする

公開場所（GitHub Release）:

**https://github.com/0kam/SnowGauge/releases/tag/fw-2026-09-04**

ページ下部の "Assets" に 3 つのファイルがあります。用途に合わせて 1 つだけ落とせば十分です。

| ファイル | 使い方 |
|---|---|
| `snowgauge_fw_2026-09-04.uf2` | **方法 A**（ドラッグ＆ドロップ）。Windows / Linux / 古めの macOS |
| `snowgauge_fw_2026-09-04_dfu.zip` | **方法 B**（シリアル DFU）。**macOS 26** ではこちらが必須 |
| `snowgauge_fw_2026-09-04.hex` | 開発者向け（自分でパッケージを作る場合）。通常は不要 |

新しい版が出ると Release のタグ名（`fw-YYYY-MM-DD`）が変わります。ファイル名の日付も同じです。

---

## 3. 方法 A: UF2 ファイルをドラッグ＆ドロップ（Windows / Linux / 古い macOS）

XIAO には「ブートローダ」という小さな書き込みプログラムが最初から入っていて、USB メモリのふりをしてくれます。そこにファイルをコピーするだけで書き込みが終わります。

1. 電池を外す（上の安全上のきまり）。
2. USB-C ケーブルで本体と PC をつなぐ。
3. XIAO の **RESET ボタン**（USB-C コネクタのすぐ横にある小さなボタン）を**すばやく 2 回**押す（ダブルクリックの要領、0.5 秒以内に 2 回）。
   - 成功すると、PC に **`XIAO-SENSE`** という名前のドライブ（USB メモリのようなもの）が現れます。
   - 現れないときは、間隔を変えてもう一度ダブルタップしてみてください。
4. ダウンロードした `snowgauge_fw_2026-09-04.uf2` を **`XIAO-SENSE` ドライブにコピー**（ドラッグ＆ドロップ）する。
5. 数秒でドライブが自動的に消え、本体が再起動します。これで書き込み完了です。
   - Windows で「ドライブが正しく取り外されませんでした」のような警告が出ても問題ありません。
6. USB を抜いてから電池をつなぐ（現地に持っていく場合）。

### うまくいったかの確認（3 つのうちどれかで OK）

| 確認方法 | 見え方 |
|---|---|
| USB シリアル（第 5 節） | `sg:~$` という入力待ち（プロンプト）が出て、`help` と打つと `cal` `cfg` `rec` などのコマンドが並ぶ |
| アプリ（04 章） | 「接続」を押すと **`SG-XXXX`**（XXXX は本体ごとの英数字 4 桁）が候補に出る |
| ドライブ | `XIAO-SENSE` ドライブが**消えたまま**で、再び出てこない |

> **緑 LED について**: この本体の緑 LED は「観測を 1 回行うたびに 50 ms 光る」だけで、起動時には光りません。書き込み直後は自動観測が約 10 分間止まる（再起動直後の保留時間）ため、**LED が光らなくても失敗ではありません**。確認には上の 3 つを使ってください。

## 4. 方法 B: シリアル DFU（macOS 26 など、ドライブが出てこない PC）

macOS 26 は XIAO の `XIAO-SENSE` ドライブをマウントできません（Finder に出てこない）。この場合は、`adafruit-nrfutil` というコマンドラインツールで書き込みます。Windows / Linux でも同じ手順が使えます。

### 4.1 一度だけ: ツールを入れる

「ターミナル」（macOS: アプリケーション → ユーティリティ → ターミナル）を開き、次を実行します（Python 3 が必要です）。

```bash
pip install adafruit-nrfutil
```

`pip` が見つからないと言われたら `pip3 install adafruit-nrfutil` を試してください。

### 4.2 本体をブートローダにする

電池を外し、USB をつないでから、どちらかの方法で本体を「書き込み待ち」状態にします。

- RESET ボタンを**すばやく 2 回**押す（方法 A と同じ）、または
- すでに SnowGauge ファームウェアが入っている本体なら、USB シリアル（第 5 節）で `dfu` と打つ。

### 4.3 ポート名を調べる

ターミナルで

```bash
ls /dev/cu.usbmodem*
```

と打つと、`/dev/cu.usbmodem21101` のような名前が出ます（数字は USB ポートによって変わります）。これが `<port>` です。
Windows では「デバイス マネージャー」→「ポート (COM と LPT)」に `COM5` のように出ます。Linux では `/dev/ttyACM0` です。

### 4.4 書き込む

ダウンロードした zip のあるフォルダで（`cd ~/Downloads` など）:

```bash
adafruit-nrfutil dfu serial --package snowgauge_fw_2026-09-04_dfu.zip -p /dev/cu.usbmodem21101 -b 115200 --singlebank
```

`-p` のあとは 4.3 で調べたポート名に置き換えます。進捗バーが 100% まで進み、`Device programmed.` と出れば完了です。本体は自動的に再起動します。確認方法は方法 A と同じです。

## 5. USB シリアルで本体と会話する（動作確認）

ファームウェアには「シェル」という文字で会話する機能があり、USB でつないだ PC から本体の状態を見たり、試しに観測させたりできます（現地では使いません。机の上での確認用です）。

### 5.1 シリアルターミナルを開く（通信速度 115200）

**macOS**（ターミナル）:

```bash
ls /dev/cu.usbmodem*                 # ポート名を調べる
screen /dev/cu.usbmodem21101 115200  # 名前は自分のものに
```

終了は `Ctrl+A` を押してから `K`、`y`。

**Windows**: Tera Term または PuTTY を使います。
- Tera Term: 起動 → 「シリアル」を選び、ポートに `COM5` など（USB シリアル デバイス）を選ぶ → 「設定」→「シリアルポート」でスピードを **115200** に。
- PuTTY: Connection type = Serial、Serial line = `COM5`、Speed = `115200` → Open。

**Linux**: `screen /dev/ttyACM0 115200`（権限エラーなら `sudo usermod -aG dialout $USER` して再ログイン）。

画面が空のままなら **Enter を 1 回**押してください。`sg:~$ ` と出れば会話できています。

### 5.2 まず打ってみるコマンド

| コマンド | 何が分かるか |
|---|---|
| `help` | コマンド一覧。`cal` と `cfg` があれば今回の版（2026-09-04 以降）です |
| `rec count` | 記録の件数、記録用ファイルシステムの状態（`fs=mounted` が正常）、最新の記録 |
| `time` | 本体の時計（UTC）と状態: `synced`（同期済み）/ `estimated`（前回記録から推定）/ `unset`（未設定） |
| `cfg show` | 観測スケジュール（開始・終了・間隔・タイムゾーン）、基準値 d0/θ0、次回の自動観測時刻 |
| `ble` | Bluetooth の広告（アプリから見えるための信号）が出ているか。`SG-XXXX` の名前もここで分かる |
| `measure` | **その場で 1 回観測**して記録に保存する。傾斜 → センサ通電 → 電池 → 距離 100 回 → 電池 → 遮断、を約 1.6 秒で行い、結果を CSV 1 行で表示 |

`measure` の結果の見方: `median`（距離の中央値 cm）、`var`（ばらつき cm²）、`strength`（信号強度）、`vbat`（電池 mV）。詳しくは `firmware/README.md` の "Shell output fields"。

### 5.3 その他の便利なコマンド

| コマンド | 説明 |
|---|---|
| `rec ls` | 記録ファイルの一覧（`rec_YYYYMM.bin`、月ごと） |
| `rec dump [n]` | 新しい方から n 件の記録を CSV で表示（省略時 10 件、`rec dump 0` で全部） |
| `rec erase ERASE` | **全記録を消す**（`ERASE` を大文字で付けないと拒否されます） |
| `time set <epoch>` | 時計を合わせる。`<epoch>` は UTC の秒数。macOS/Linux のターミナルで `date +%s` と打つと今の値が出ます。通常はアプリの「同期」で合わせるので不要 |
| `cfg sched <開始 HH:MM> <終了 HH:MM> <間隔 分> [tz 分]` | スケジュール設定（例 `cfg sched 00:00 00:00 180 540` = 終日 3 時間ごと、日本時間） |
| `cal zero [積雪深 cm]` | 基準値を取る（アプリの「ZERO」「積雪深で基準設定」と同じ） |
| `cal clear` | 基準値を消す |
| `batt` | 電池電圧 |
| `tilt` | 傾斜角 |
| `rail on` / `rail off` / `rail status` | センサ電源の入・切・状態（`tfmini read` の前に `rail on` が必要） |
| `tfmini read [n]` | 距離センサから n 回読んで統計を表示 |
| `auto <秒>` | 机上テスト用: 指定秒ごとに自動観測（`auto 0` で止める）。スケジュールより優先されます |
| `reboot` | 再起動 |
| `dfu` | ブートローダに入る（方法 B の書き込み待ち状態） |

> 開発用の新品ボードには、動作テスト用の基準値 d0 が入っていることがあります。**現地に設置するときは必ずアプリで ZERO か「積雪深で基準設定」をやり直してください**（04 章）。

## 6. 困ったとき

| 症状 | 対処 |
|---|---|
| `XIAO-SENSE` ドライブが出てこない | (1) macOS 26 → 方法 B。(2) ケーブルが充電専用でないか確認（別のケーブルを試す）。(3) ダブルタップの速さを変えて再挑戦。(4) PC の別の USB ポートに挿す。(5) USB ハブ経由をやめて直挿し |
| 方法 B で転送が途中で止まり、本体が再起動してしまう | 自分で `adafruit-nrfutil dfu genpkg` した zip の場合、`--sd-req 0xFFFE` を付けていないと（`0x00` だと）ブートローダが拒否します。Release の zip は正しく作ってあるので、まず Release の zip を使ってください |
| 方法 B で `No such file or directory: '/dev/cu.usbmodem…'` | ポート名が違います。4.3 をやり直す。ブートローダに入る前後で番号が変わることがあります。Windows は `COM5` のような名前 |
| 方法 B で `Timeout` | 本体がブートローダになっていません。RESET をダブルタップしてから 10 秒以内にコマンドを実行 |
| ドライブが何度も出てくる / アプリに `SG-XXXX` が出ない | アプリのプログラムが起動していません（ブートローダのまま）。RESET を **1 回**押してみる。直らなければもう一度書き込む |
| シリアルで何も出ない | Enter を押す。別のプログラム（Arduino IDE のシリアルモニタ、もう 1 つの `screen`）がポートを使っていないか確認。ケーブルを挿し直す |
| シリアルに文字化け | 速度が 115200 になっているか確認 |
| `time` が `unset` のまま | 正常です（電源を入れ直すと時計はリセットされます）。現地でアプリの「同期」を押せば合います |

## 補足

- 書き込みが終わったら **USB を抜いてから電池（または電源）をつなぎ直して**ください。基板は電源が入ると数秒で `SG-XXXX` として BLE に現れ、アプリから見えるようになります。
- 書き込み直後の本体には、開発時に試験用の基準値（d0）や観測スケジュールが残っていることがあります。設置時にアプリで基準を取り直し、スケジュールを確認してください（[04_app.md](04_app.md)）。
